# Frontend design

Work within the task's authority. Establish what the user needs to understand or do and the existing product conventions that govern the surface.

## Set the direction

Before building, identify the first thing the eye should land on, the next meaningful action, and one specific design move that serves this subject. Use a small layout sketch when order or placement is uncertain.

- **Operational UI.** Read the nearest implemented peer for shell, type roles, spacing, controls, and action placement. Treat it as the visual reference. Start around the user's next decision. Group fields by dependency and keep actions with their owner. Before reorganizing, identify the meaningful data, status and actions the user needs to retain. Consolidate repeated status into one place in its owning view. Use accent and weight for decisions and errors. Fit settings and dialogs to constrained height with intentional scrolling, reachable actions, and stable layout as states change. Plan keyboard focus, dismissal, draft preservation, validation and retry.
- **Persuasive or editorial UI.** Compose the first viewport around one strong image, object or typographic idea drawn from the subject. Make the identity, offer and next action legible as a group. Choose the image crop, headline breaks, type scale and alignments together. Set an intentional foreground and background rhythm as the page moves from promise to concrete details to action. Use relevant content and earned contrast to create character. Avoid filler such as invented testimonials, decorative badges, repeated cards and empty calls to action.
- Use the product's established identity for maintenance. For material composition, type, color, motion or visual refinement, apply the relevant parts of the [pinned visual direction reference](references/vendor/anthropic/frontend-design.md) within the brief and applicable conventions.

## Inspect and refine

Run the normal browser or native surface and inspect actual screenshots at an ordinary size and the narrowest relevant size. Also look at a consequential state such as a long list, validation or success. Check the visual reading order at a glance, then inspect crop, type breaks, alignment, density and contrast at full size. Compare established UI beside a nearby screen. Walk the primary interaction with keyboard and pointer where applicable.

Make the largest correction the evidence warrants and recapture that view. Verify measurable behavior such as overflow, visible actions, focus and state persistence in the runtime. Record observed results and label unavailable visual acceptance as unverified.
